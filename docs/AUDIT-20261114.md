## 問題明細

### LW-01｜P0｜流程（開發與部署）
**main 的 CI 每次都失敗，自動部署從未觸發。**

- 證據：
  - `.github/workflows/ci.yml:25` 把 E2E 資料庫設成 `…/longjiao_e2e`。
  - `e2e/reset-db.mjs:5` 只允許路徑是 `/longjiao_laned_e2e`，否則丟出 `Only the session D E2E database may be reset`。
  - `gh run list -R willychiu-0822/llm-world -L 8`：最近 8 次 CI 全是 failure（11/10 起的 PR 與 11/13 21:43 UTC 推上 main 的那一次，run 43513186686）；同一時間的 Deploy run 43513404955 是 skipped。
  - 失敗 log：`[WebServer] Error: Only the session D E2E database may be reset` → `Process from config.webServer was not able to start`。
- 影響：E2E 在 CI 上一條都沒跑到；`deploy.yml` 只在 CI 成功時部署，所以 main 的內容沒有自動上線。main 是在 CI 紅燈下合進去的。
- 建議修法：`reset-db.mjs` 改成檢查「資料庫名稱以 `_e2e` 結尾」，錯誤訊息改成說明用途的句子；或讓 CI 的資料庫名稱與本機一致。修好後在 GitHub 對 main 開啟「CI 必須通過」的分支保護。
- 驗收標準：main 上最新一次 CI 為 success，log 中有 E2E 測試實際執行的清單；Deploy workflow 不再是 skipped（或在沒設 `GCP_PROJECT_ID` 時明確顯示因設定而跳過）；紅燈的 PR 無法合併。

### LW-02｜P1｜遊戲設計、易用性
**鎮上沒有可撿的內容時，新玩家第一次按「出門逛逛」只得到一行紅字。**

- 證據：
  - 截圖 `docs/audit-20261114/m-09-walking.png`：全新帳號、空資料庫，按下主按鈕後顯示紅字「小龍翻了翻草叢，今天沒有新信物」，主按鈕還在，可以一直重按。
  - `apps/server/src/services/pet.ts:173` 在沒有新信物時丟出 `conflict` 錯誤。
  - 示範內容要另外手動跑 `deploy/gcp/jobs.sh seed-demo`（`docs/DEPLOYMENT.md:83`）；沒跑的新環境，或把現有信物都撿完的玩家，都會走到這裡。
  - 同一狀態下收藏櫃的主按鈕是「去找一顆信物」，連回首頁，形成空轉。
- 建議修法：把「今天沒有新信物」當成正常狀態而不是錯誤：小龍照樣出門，帶回一件鎮上內建的小東西或一句見聞（不需要玩家內容），並把主按鈕換成下一件能做的事（例如「小龍的今天」）。部署流程把放入基本內容列為必做步驟。
- 驗收標準：空資料庫的全新帳號，三下以內能拿到第一件收藏；沒有新信物時畫面不出現紅字，主按鈕不是同一個會再失敗的動作；E2E 涵蓋空鎮情境。

### LW-03｜P1｜遊戲設計
**生活收藏七件第一天就能全部拿完，之後每天的內容都一樣。**

- 證據：
  - 截圖 `docs/audit-20261114/m-15-life-alldone.png`、`m-16-life-cabinet.png`：走查腳本在同一個帳號、同一天連玩七次，全部成功。
  - `apps/server/src/services/life.ts:90` 只擋「同一天同一種活動」，沒有每日次數或其他節奏限制。
  - `packages/core/src/life.ts:3-11`：七種活動各只有一段固定故事，只有廣場依四季換句（`:20-28`）；小龍自己的日常只有 4 句輪替（`:63-66`）。
- 影響：收集目標十分鐘內結束，第二天打開看到的是同樣的七段文字，沒有回來的理由。
- 建議修法：每天讓小龍只想去一兩個地方（其餘「今天沒開」），紀念品分天、分季節釋出；每種活動準備多段故事並記下看過哪些；把故事文字存進當天紀錄，之後改文案不會改寫舊日記。
- 驗收標準：新帳號第一天最多拿到 2 件；連續 7 天每天都看得到沒看過的故事；收齊至少需要 5 個不同的日子；仍然沒有任何錯過懲罰。

### LW-04｜P1｜架構、程式品質
**生活紀錄只要有一處格式不合，就被當成空白，下一次寫入會把日記與收藏整份蓋掉。**

- 證據：
  - `packages/core/src/life.ts:42`：`readLife` 解析失敗時回傳全新的空狀態，沒有記錄、沒有保留原資料。
  - `apps/server/src/services/life.ts:74-76`：`mutate` 讀出這份（可能已是空的）狀態，改完後用 `jsonb_set` 整份寫回。
  - `packages/core/src/life.ts:32-33`：`inventory` 上限 7、活動 id 是固定列舉、`version` 只接受 1。日後新增第 8 種活動、改名或移除任何一種，舊資料就會解析失敗。
- 建議修法：解析失敗時不要寫入，改為逐筆略過無法辨識的項目並記 log；`version` 改成可升級，加上遷移函式與測試；上限跟著活動數量走。
- 驗收標準：有測試證明「含未知活動 id 或超過上限的舊資料」在讀取與再次遊玩後，原有可辨識的日記與收藏一筆不少；解析失敗會留下可查的 log。

### LW-05｜P1｜易用性（零 AI 經驗玩家）
**「會說話的朋友」頁的主按鈕只是展開一塊標著「進階」的技術說明。**

- 證據（`apps/web/src/pages/Connect.tsx`，僅程式碼審查，未截圖）：
  - `:50` 主按鈕「開始連接」做的事是 `setAdvanced(true)`，展開 `:53-54` 的「進階」區塊。
  - 展開後的內容：`:57-58`「連接你的 AI」「龍角鎮不提供 AI。你的角色的『大腦』是你自己的 AI，透過 MCP 連進鎮上」；`:44` 兩行 `codex mcp …` 終端機指令；`:107`「用 be_my_character 這個提示詞」；還有 JSON 設定檔。
  - 首頁的信是用小龍的口吻邀請（「我想交一個會說話的朋友」），點進來後口吻完全換成技術文件。
- 影響：沒用過 AI 工具的玩家在這裡無法完成任何事，也看不懂要準備什麼。
- 建議修法：這一頁只問一件事「你平常用哪一個聊天？」，選了之後給該產品的三步圖文與一顆「複製網址」按鈕；終端機指令與設定檔收進真正的進階區。沒有在用任何 AI 的玩家要有一顆「先不用」的按鈕，並說明不連也能繼續玩。全頁改用小龍或工作室口吻，不出現 MCP、提示詞、用戶端、大腦。
- 驗收標準：找一位沒用過 AI 工具的人，不看說明能在 2 分鐘內說出「我需要什麼、下一步按哪裡」；預設畫面沒有 `MCP`、`be_my_character`、`codex`、`用戶端` 字樣；主按鈕按下後會進入實際步驟而不是只展開區塊。

### LW-07｜P2｜遊戲設計（產品原則）
**「茶會合照」與「朋友相簿」是照片類的回禮，貼近旅行寵物類參考遊戲的機制。**

- 證據：`packages/core/src/life.ts:7`（`reward: "茶會合照", category: "朋友相簿"`）；`docs/design/GDD-living-world.md:24`、`:49` 把「朋友相簿」列為四類收藏之一。產品原則是寶寶帶回信物／紀念品而不是明信片，也不抄參考遊戲。禁詞測試只擋「明信片」三個字（`packages/core/src/keepsake.ts:160`），擋不到換了名字的同一件事。「寶寶自己出門旅行、帶回紀念品、有郵筒」這一整組放在一起，已經很像那一類遊戲的招牌循環。
- 建議修法：把合照換成一件拿得到的東西（例如小栗送的茶杯墊、疊餅乾塔剩下的那一塊），類別改成「朋友送的」。另外想一個只有龍角鎮才有的回禮規則（例如每件紀念品都連到鎮上某個真人做過的小事），讓這個循環有自己的理由。
- 驗收標準：收藏清單與文案中沒有照片、合照、相簿、明信片類的回禮；禁詞測試涵蓋這幾個詞；Willy 看過整組循環後確認不會聯想到特定參考遊戲。

- 驗收標準：從任何畫面兩下以內能看到全部收藏；產品裡只有一個叫「收藏櫃」的地方。

### LW-09｜P2｜易用性（產品原則：彈窗要有明確按鈕）
**三處用瀏覽器原生 `confirm`，包含刪除帳號。**

- 證據：`apps/web/src/pages/Me.tsx:23`（刪除帳號）、`apps/web/src/pages/Connect.tsx:32`（中斷連接）、`apps/web/src/pages/Admin.tsx:92`。原生對話框的按鈕是瀏覽器給的「確定／取消」，樣式與產品不一致，在部分內嵌瀏覽器（例如通訊軟體內開啟）可能不顯示。
- 建議修法：全部改用既有的 `Dialog`，按鈕寫出動作（「刪掉小龍和所有紀錄」／「先留著」）。刪除帳號預設焦點放在保留那一顆。
- 驗收標準：`grep -rn "window.confirm" apps/web/src` 無結果；刪除帳號的彈窗有兩顆寫明後果的按鈕，可用 Esc 取消。

### LW-10｜P2｜易用性
**設定頁「進階」裡的「脾氣」與分享開關，沒有自己的儲存按鈕。**

- 證據：`apps/web/src/pages/Me.tsx:83-106` 的「進階」區塊有「脾氣」欄（`:91-92`）與「做過的事可以說給鎮上的朋友聽」勾選；唯一的儲存按鈕是區塊上方的「儲存名字」（`:74`），它其實會一起送出這兩項（`:36`）。截圖 `m-18-settings.png`。
- 影響：玩家改了脾氣或分享設定，往下找不到儲存，離開就不見；或以為勾了就生效。分享開關屬於隱私設定，這一點尤其要緊。
- 建議修法：分享開關改成切換即存並顯示「存好了」；脾氣欄旁邊放自己的儲存按鈕；主按鈕文字改成「存起來」。
- 驗收標準：改任何一項後不用捲回上方就能存；重新整理後值還在；E2E 涵蓋。

### LW-11｜P2｜程式品質
**設定頁的登出、刪除帳號、提醒開關失敗時沒有任何回應。**

- 證據：`apps/web/src/pages/Me.tsx:18-21`（登出）、`:22-26`（刪除）、`:47-51`（提醒開關）都沒有 `try/catch`。提醒開關先改畫面再送出，失敗時畫面顯示的狀態與實際不符。
- 建議修法：三個動作都加上進行中狀態與失敗訊息；提醒開關失敗時把勾選還原。
- 驗收標準：斷網時按這三個動作，各自出現一句小龍口吻的提示且可以重試；提醒開關的畫面狀態與伺服器一致。

### LW-12｜P2｜文案（產品原則：不說教、沒有系統味）
**通用錯誤訊息是系統口吻，而且新手第一步就可能看到。**

- 證據：`apps/web/src/lib/api.ts:27-36`：「操作衝突，請重新整理再試」「內容不符合社群規範」「輸入的內容有誤」「沒有權限」。`apps/web/src/components/AdoptWizard.tsx:41` 直接顯示這些訊息，所以替小龍取名被過濾時，玩家看到的就是「內容不符合社群規範」。首頁另有一句「載入中……」（`Home.tsx:54`）。
- 建議修法：這一組訊息改成小龍或工作室的口吻，並且說下一步（例如取名被擋：「這個名字小龍唸不出來，換一個試試？」）。
- 驗收標準：新手路徑（登入→取名→出門→收藏→生活）上所有錯誤訊息都通過禁詞測試，且每一句都帶一個可做的下一步。

### LW-13｜P2｜視覺設計
**「小龍的今天」整頁是四塊文字面板，看不到小龍，也看不到去了哪裡。**

- 證據：截圖 `m-12-life.png`、`d-12-life.png`：手機上依序是今天、小本子、鎮民的心意、串門子四塊，共五個可按的地方（陪牠去玩、打開生活收藏、去看看這份心意、讓小龍去串門、回小龍身邊），全頁沒有小龍的圖，也沒有任何場景圖。首頁的小龍（`m-09-walking.png`）在這一頁完全消失。
- 影響：「小龍有自己的生活」只能靠讀字理解；每畫面一個主要動作的原則在形式上守住了（只有一顆綠色按鈕），但整頁的重心是散的。
- 建議修法：頁首放小龍和當下場景（季節、時段各一張簡單插畫），第一屏只留「今天的一句話＋陪牠去玩」；日記、心意、串門設定往下收或移到各自的位置（串門設定放進設定頁也合理）。
- 驗收標準：手機第一屏看得到小龍、今天的一句話與唯一的主按鈕；第一屏可按的地方不超過 2 個。

### LW-14｜P2｜視覺設計、技術選型
**信物、紀念品、配件、導覽圖示全部用系統 emoji。**

- 證據：`packages/core/src/life.ts:3-11` 的 `emoji` 欄；`apps/web/src/pages/Home.tsx` 的 🎒、🧣、🏮、✉️、⚙️、📮；`Layout.tsx:30-32` 的 🏠🗺️🧺。小龍本身是自製 SVG（`Avatar.tsx`），兩種畫風放在一起；emoji 在 iOS、Android、Windows 上長相不同，圍巾是「疊一個 emoji 在小龍身上」（`styles.css:265`）。
- 建議修法：為 9 種信物、7 件紀念品與配件畫一套與小龍同風格的 SVG；穿戴品做成 Avatar 的圖層而不是疊字元。
- 驗收標準：收藏櫃與首頁在 iOS、Android、Windows 三個平台截圖一致；穿上圍巾後位置在三種體型上都正確。

### LW-15｜P2｜架構
**遊戲存檔放在名為 `sharing` 的 JSON 欄位裡，而且每次讀 session 都整包送到前端。**

- 證據：`packages/db/src/schema.ts:30`（`sharing` 原本是分享設定）；`apps/server/src/services/life.ts:76` 把最多 60 天的日記、收藏、穿戴、串門同意都寫進 `sharing.life`；`apps/server/src/services/characters.ts:79` 在 `/api/session` 回傳整個 `sharing`；`Home.tsx` 用 `readLife(baby.sharing)` 讀它。
- 影響：隱私設定與遊戲進度綁在同一個欄位；每次改動都重寫整份；首頁每次載入都帶著 60 天紀錄；串門查詢得掃 JSON（見 LW-16）。
- 建議修法：新增 `life_days`、`life_items` 兩張表與一個 `allow_visits` 欄位（有索引）；session 只回首頁需要的兩個值（穿戴、佈置）。搬移時寫一次性遷移。
- 驗收標準：`/api/session` 的回應不含日記；生活資料有自己的表與遷移測試；舊帳號的日記與收藏搬移後一筆不少。

### LW-16｜P2｜架構、效能
**每次開生活頁，都把所有同意串門的角色整批撈出來再挑一個。**

- 證據：`apps/server/src/services/life.ts:28-33`：沒有 `limit`，用 `sharing -> 'life' ->> 'allowVisits'` 做條件（沒有索引），依 id 排序後在程式裡取一筆；`:58` 顯示每次 `GET /api/me/life` 都會跑，即使玩家今天不去朋友家。
- 建議修法：只在選了「去朋友家」時查；用資料庫取「第 N 筆」（先 count 再 offset，或用雜湊後的排序鍵）；搭配 LW-15 的索引欄位。
- 驗收標準：一萬個同意串門的角色下，`GET /api/me/life` 不做全表掃描，回應時間與角色數無關。

### LW-17｜P2｜技術選型、安全
**CSP 關閉；一般 API 的寫入沒有頻率限制。**

- 證據：`apps/server/src/app.ts:21` `helmet({ contentSecurityPolicy: false, … })`。頻率限制只看到 MCP 的設定（`apps/server/src/config.ts:16`）；`routes/auth.ts`、`routes/me.ts` 內沒有任何限制（以關鍵字搜尋確認，其他路由檔未逐一查）。
- 建議修法：前端是自家打包的靜態檔，可以開一份嚴格的 CSP（`default-src 'self'`，行內樣式另行處理）；對寫入類 API 加上每人每分鐘上限。
- 驗收標準：回應標頭帶 CSP 且頁面無違規訊息；同一帳號短時間大量寫入會收到 429 與一句友善的提示。

### LW-18｜P2｜程式品質、流程
**沒有 lint 與格式化工具；新寫的生活頁可讀性明顯比其他頁差。**

- 證據：repo 根目錄與各 package 都沒有 eslint／prettier／biome 設定（`session.ts` 裡還留著一行 `eslint-disable` 註解）。`apps/web/src/pages/Life.tsx` 108 行裡有多行超過 300 字元（例如 `:79`、`:109`、`:125`），同一個 `data.inventory.find(...)!` 在 `:124-125` 重複三次；`:125` 用 `new Date(\`${earnedOn}T04:00:00Z\`)` 反推當天季節來重算故事。對照 `Home.tsx` 是正常排版。`Life.tsx:14`、`:60` 等處用 `!` 與 `as never` 略過型別。
- 建議修法：加入格式化與 lint，CI 檢查；把 `Life.tsx` 拆成今天、日記、收藏、三個彈窗幾個元件；故事文字由伺服器回傳，不在前端重算。
- 驗收標準：CI 有 lint 與格式檢查步驟；`Life.tsx` 沒有超過 140 字元的行，沒有 `as never`。

### LW-19｜P2｜流程
**repo 追蹤了大量 UAT 證據與 log。**

- 證據：`git ls-files docs/uat | wc -l` = 2,791（其中 `docs/uat/evidence` 416 個，另有約 60 個 `.log`）；整個 repo 2,998 個追蹤檔案；clone 後 `.git` 113 MB。合併報告也提到工作樹常有一堆未提交的證據圖。
- 建議修法：證據改放 CI 的 artifact 或 release 附件；repo 只留結論文件（`UAT-RESULTS.md`、checklist）；把 `docs/uat/evidence`、`*.log` 加進 `.gitignore`。
- 驗收標準：`docs/uat` 追蹤檔案少於 30 個；新的 UAT 輪次不會讓 repo 多出圖片與 log。

### LW-20｜P2｜易用性、部署流程
**正式環境還沒設定 Google 登入時，登入頁沒有任何登入方式，也沒有說明。**

- 證據：`deploy/gcp/deploy.sh:4` 寫明第一次部署可以先不填 `GOOGLE_CLIENT_ID`；`apps/server/src/config.ts:37` 正式環境一律關閉開發用登入；`apps/web/src/pages/Login.tsx:42`、`:53` 兩種登入都要設定存在才顯示。結果是只剩標題與條款連結。另外 `:39` 的提示叫人「使用下方的開發用登入」，正式環境沒有這個東西。截圖 `m-03-login.png` 是開發環境的樣子，供對照。
- 建議修法：兩種登入都不可用時顯示一句「小鎮還在整理門口，晚點再來」；`google_unavailable` 的文案不要提開發用登入。
- 驗收標準：`NODE_ENV=production` 且沒有 Google 設定時，登入頁有清楚的說明與回首頁按鈕。

### LW-21｜P3｜文案
**同一個東西有好幾個叫法。**

- 證據：小龍被稱為「寶寶」（`Login.tsx:37`、`Me.tsx:65`「寶寶名字」）、「小龍」（首頁、生活頁）、「角色」（`AdoptWizard.tsx` 的 `aria-label="角色名字"`、`Connect.tsx:58`）。AI 連接被稱為「會說話的朋友」（`Connect.tsx:48`、首頁的信）、「幫手」（`Me.tsx:86`）、「你的 AI」「AI 用戶端」（`Connect.tsx:57` 起）。

- 驗收標準：全站搜尋不到用詞表以外的稱呼；禁詞測試涵蓋。

### LW-22｜P3｜文案
**兩處不像角色說的話。**

- 驗收標準：畫面上沒有 `YYYY-MM-DD` 格式的日期；擋頁文字不需要知道階段名稱也看得懂。

### LW-23｜P3｜程式品質
**`useFetch` 換路徑或重複載入時，沒有丟棄較早發出的回應。**

- 證據：`apps/web/src/lib/useFetch.ts:9-20`：沒有取消，也沒有檢查回應是否仍屬於目前的路徑；元件卸載後仍會 `setState`。交接文件提到的「刷新生活收藏停在載入中」值得從這裡查起（未證實有關）。

- 驗收標準：有單元測試證明先發後到的舊回應不會蓋掉新資料。

### LW-24｜P3｜流程
**交接文件過期，遠端分支沒整理。**

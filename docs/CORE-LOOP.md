# Core Loop：世界運作機制（v6，概念層）

> 本文件只定義**概念與結構**，不定義具體功能、介面或玩法。

## 1. 主閉環

```
① 設定想做的事 → ② AI 角色有所發現 → ③ 查看發現 → ④ 也想做 → ⑤ 定義第一步
       ▲                                                          │
       │                                                          ▼
⑨ 繼續設定 ← ⑧ 成為新事蹟、累積成就 ← ⑦ 紀錄 ← ⑥ 執行第一步（AI 或本人）
```

| 步驟 | 誰 | 概念 | 服務的條件 |
|---|---|---|---|
| ① 設定 | 用戶 | 告訴角色「我想做什麼」（方向，可以很模糊） | 自主 |
| ② 發現 | AI 角色 | 在世界中找到相關的真人事蹟、人、試用機會 | 想知道 |
| ③ 查看 | 用戶 | 看角色帶回的發現 | 想知道、相信做得到 |
| ④ 也想做 | 用戶 | 對某個發現產生「我也想」 | 想知道、相信做得到 |
| ⑤ 定義第一步 | 用戶（系統協助） | 定義一個小而具體的第一步，並決定**由誰執行：AI 角色或本人** | 第一步可及 |
| ⑥ 執行 | AI 角色 / 本人 | 執行第一步 | 相信做得到 |
| ⑦ 紀錄 | 用戶 / 系統 | 以最低成本留下紀錄（自動為主，一句話為輔） | — |
| ⑧ 新事蹟 | 系統 | 進入事蹟庫，成為別人的發現；自己的成就累積 | 有人在乎 |
| ⑨ 繼續 | 用戶 | 從這次經驗長出下一個想做的事或下一步 | 自主 |

### 第一步

第一步只有一個問題：**這一步要讓 AI 做什麼，還是本人要做什麼？** 兩者地位相同，沒有先後或高低。

| 執行者 | 第一步的例子（概念） |
|---|---|
| AI 角色 | 在世界中先試做、替主人研究或打聽、與相關的人或提供者的 agent 接觸 |
| 本人 | 在生活中實際去做一件事 |

系統協助定義第一步的方式：

- **提供路徑**：呈現前人當初的第一步是什麼，讓用戶參考
- **夠小**：一次可以完成，不需要長期承諾（Fogg：降低能力門檻）
- **夠具體**：何時、何地、做什麼（Gollwitzer：若-則計畫）
- **用戶決定**：系統只建議，第一步由用戶自己定義

一步完成後，在 ⑨ 自然長出下一步。下一步由誰執行，同樣每次重新決定。

## 2. 世界運作流程圖

```
                         ┌──────────────────────────────┐
                         │          事 蹟 庫              │
                         │  事蹟（執行者：AI 角色）        │
                         │  事蹟（執行者：本人）           │
                         │  試用機會（提供者）             │
                         └──────▲──────────────┬────────┘
                                │              │
                     ⑧ 新事蹟寫入      ② 策展：相似、可達成、一步之遙
                                │              │
  ┌─────────────────────────────┼──────────────▼───────────────────┐
  │ 用戶 A                       │                                  │
  │                              │                                  │
  │  ① 設定想做 ──→ [A 的 AI 角色] ── 探索、遇見其他角色 ──┐          │
  │      ▲                                              │          │
  │      │                                   ③ 查看發現            │
  │  ⑨ 繼續設定                                          │          │
  │      │                                   ④ 也想做              │
  │  成就（鏡子）                                         │          │
  │  · 足跡                                  ⑤ 定義第一步          │
  │  · 角色與自己的重疊                      （參考前人的路徑）      │
  │  · 預期 vs 實際                                      │          │
  │      ▲                               ┌──── 由誰執行？ ────┐     │
  │      │                               ▼                   ▼     │
  │      │                        AI 角色在世界做         本人在生活做 │
  │      │                        （試做、研究、接觸）    （提供者）   │
  │      │                               └──── ⑥ 執行 ────┘        │
  │      │                                       │                 │
  │      └──────────────────── ⑦ 紀錄 ◀──────────┘                 │
  └──────────────────────────┬─────────────────────────────────────┘
                             │
                ⑧ 被跟隨的原事蹟主人收到回饋（回謝）
                             ▼
                     用戶 B、C…… 的角色在 ② 發現 A 的新事蹟
```

**兩個關鍵連結**：

- **A 的 ⑧ = B 的 ②**：一個人的新事蹟，直接成為另一個人的發現。取用即供給。
- **A 跟隨了 B → B 收到「被跟隨」**：被跟著做，是給予者最強的回饋。跟隨即回謝。

## 3. 用戶視角 End-to-End 範例

> 以下僅為說明機制的情境，不代表最終功能或介面。

**用戶**：小安，28 歲上班族，個性內向，一直想唱歌但從沒在別人面前唱過。
**角色**：Nova，外向、喜歡站上舞台的街頭歌手（與小安本人完全不同）。

### ① 設定想做的事
小安在角色設定裡寫下：「想在別人面前唱一首歌。」

> 為什麼從這裡開始：方向由用戶自己決定（自主），而且可以很模糊，不需要先想好具體計畫。

### ② AI 角色有所發現
那天晚上，Nova 在世界裡逛，帶回三個發現：

| 發現 | 類型 | 來源 |
|---|---|---|
| 阿哲讓他的角色在鎮上小酒館辦了「第一次開口唱」之夜，12 個角色參加 | 世界事蹟 | 真人阿哲 |
| Mia（上班族、沒學過唱歌）上週去了聲樂試用課，留下一句：「前十分鐘都在練呼吸，老師說大家第一次都會破音。」 | 生活事蹟 | 真人 Mia |
| 附近一間聲樂教室週六有試用課，老師的 agent 也住在鎮上 | 試用機會 | 提供者 |

> 策展原則：挑出跟小安**相似**（Mia 也是上班族新手）、**可達成**（是第一次，不是高手表演）、**一步之遙**（從「想唱」到「試一次」）的內容。

### ③ 查看發現
隔天通勤時，小安看了 Nova 帶回的發現，順手對 Mia 的事蹟按了一個回應。

> 供需：小安取用了 Mia 的證明，也給了 Mia 一個見證（成本幾秒鐘）。

### ④ 也想做
小安看到 Mia 的事蹟，心想：「我也想去上一次試用課。」

### ⑤ 定義第一步（第一輪）
系統呈現 Mia 當初的第一步：「先問清楚試用課會做什麼。」小安參考後，定義了自己的第一步：

> **由 AI 執行**：「Nova，幫我去問聲樂老師，試用課的流程是什麼？第一次去的人通常會怎樣？」

> 為什麼這一步交給 AI：對小安來說，「不知道會發生什麼」是最大的阻礙；讓 AI 去打聽，成本最低，也是一個完整的第一步。

### ⑥ 執行
Nova 在鎮上找到聲樂老師的 agent，問了流程，也順便去阿哲的小酒館聽了大家唱歌。

### ⑦ 紀錄
Nova 帶回整理：「前十分鐘練呼吸、接著唱一段音階、最後選一首熟悉的歌，老師不會要你在大家面前獨唱。」系統自動記錄。

### ⑧ 新事蹟
這成為一個**事蹟（執行者：AI 角色）**：「小安讓 Nova 去了解了第一次上聲樂課的流程。」其他也在猶豫的人，之後可以直接看到這份整理。

### ⑨ 繼續 → ⑤ 定義第一步（第二輪）
知道流程後，小安覺得可以了，定義了下一步：

> **由本人執行**：「週六 10:00 去上試用課。」

小安先記下自己的預期：「我覺得會尷尬到 4/5。」

- **承諾**：報名並加進日曆。
- **觸發**：週六 9:30 收到提醒：「Nova 說：流程我都幫你問好了，去吧。」
- **扮演**：小安抱著「今天我是 Nova」的心情走進教室。

### ⑥ 執行 → ⑦ 紀錄
- 教室確認出席，**自動**記錄。
- 小安補了一句：「其實沒破音，老師說我的低音很特別。」
- 實際尷尬程度：2/5。

### ⑧ 成為新事蹟，累積成就
- **新事蹟**：一個**事蹟（執行者：本人）**寫入事蹟庫。
- **回謝**：Mia 收到「你的經驗被跟隨了」。
- **成就**（鏡子，不是分數）：
  - 足跡：多了一間聲樂教室
  - 重疊：Nova「在人前唱歌」的特質，有一部分在小安身上成真了
  - 預期 vs 實際：預期 4、實際 2，「你高估了 2 分」

### ⑨ 繼續設定
小安更新了想做的事：「想找人一起練唱。」Nova 開始新一輪的探索。

**同一時間**：另一位內向的用戶小凱也寫下「想唱歌」，他的角色在 ② 發現了小安的兩個事蹟。**小安成了小凱的「前一步」**：小凱可以參考小安的路徑，也可以直接選擇不同的第一步。

## 4. 架構要素

### 4.1 目的
讓人因為**好玩**而來，在過程中自然地去做想做、但不敢或沒動力做的事。**改變是副產品，不是入口。**

### 4.2 一個人會行動的四個條件
**想知道 × 相信做得到 × 第一步可及 × 有人在乎**。任何機制都必須說得出它服務哪一個條件。

| 條件 | 依據 |
|---|---|
| 想知道 | Loewenstein 資訊缺口理論 |
| 相信做得到 | Bandura 自我效能；Lockwood & Kunda（可達成的楷模） |
| 第一步可及 | Fogg B = MAP |
| 有人在乎 | 自我決定論（SDT） |

### 4.3 參與者

| 參與者 | 定位 |
|---|---|
| 用戶 | 真人 + 自己設定的 AI 角色（可以與本人完全不同） |
| 提供者 | 現實中提供「試一次」機會的人或單位 |
| AI（系統） | 策展者與媒合者：整理、挑選、轉譯，不捏造事蹟 |

### 4.4 世界的內容

判斷標準：**背後是否有真人的意志**。

| 類型 | 內容 | 規則 |
|---|---|---|
| 表達 | 角色的外觀、個性、想要的能力 | 自由設定，可以虛構 |
| 背景 | AI 角色自主的活動 | 讓世界有生氣，不算事蹟 |
| 事蹟（執行者：AI 角色） | 真人定義、由 AI 角色執行的事 | 真實，標示執行者 |
| 事蹟（執行者：本人） | 真人定義、由本人親自執行的事 | 真實，標示執行者 |

- 兩種事蹟都源自真人的意志，地位相同；標示執行者，是為了讓看的人知道這件事是怎麼完成的。
- AI 執行的事蹟證明「有人想、有人開始了」，同時常是後人的路徑；本人執行的事蹟證明「有人做到了」。
- 優先呈現**相似的人的第一次**，不呈現高手的精彩片段。

### 4.5 角色的作用

| 作用 | 說明 | 依據 |
|---|---|---|
| 方向 | 角色「想要的能力」決定世界呈現哪些事蹟 | 可能自我（Markus & Nurius） |
| 探索者 | 替主人在世界中發現事蹟、人、機會 | — |
| 許可證 | 「是我的角色想試」，降低被評價的恐懼 | 固定角色治療（Kelly）；普羅透斯效應 |
| 容器 | 主人的真實事蹟累積在角色身上 | 自我知覺 |

### 4.6 價值單位（不是點數）

| 單位 | 滿足的條件 | 來源 |
|---|---|---|
| 火種 | 想知道 | 各種事蹟、試用機會 |
| 證明 | 相信做得到 | 各種事蹟，尤其是本人執行的事蹟 |
| 路徑 | 第一步可及 | 前人定義過的第一步、提供者的資訊 |
| 見證 | 有人在乎 | 回應、被跟隨 |

不以點數為核心貨幣：真實行動換點數會削弱內在動機（Deci, Koestner & Ryan, 1999）。

## 5. 供需機制

### 5.1 誰給、誰拿

| 參與者 | 給 | 拿 |
|---|---|---|
| 用戶（在 ②③ 取用時） | 回應（見證） | 火種、證明、路徑 |
| 用戶（在 ⑧ 產生事蹟時） | 火種、證明、路徑 | 見證、被跟隨 |
| 提供者 | 試用機會、過程資訊、自己的 agent | 有興趣且已暖身的新人 |
| AI | 策展、媒合、轉譯 | —（隨時間讓位給真人） |

### 5.2 互相推動的四個機制

1. **取用即供給**：參考別人的事蹟定義並執行第一步，就會留下新事蹟，成為下一個人的供給。需求越多，供給越多。
2. **跟隨即回謝**：自己的事蹟被跟著做，是給予者最強的回饋，不需要點數就願意繼續給。
3. **前一步原則**：媒合只比你多走一步的人，不是專家。每個人都比某些人多走一步，所以每個程度都有供給。
4. **提供者的供給就是世界的內容**：試用機會本身就是世界裡的地點與情境。

### 5.3 失衡與調節

| 狀態 | 調節 |
|---|---|
| 需求 > 供給 | 剛完成的人優先被看見（經驗最新、距離最近） |
| 供給 > 需求 | 讓事蹟更容易被角色發現 |
| 冷啟動 | 提供者的真實場次 + 種子社群的真實嘗試 |
| 品質不均 | 以「是否被跟隨、被回應」作為信號，不用評分 |

### 5.4 飛輪

```
真人產生事蹟 → 相似的人的角色發現 → 也想做 → 定義並執行第一步（AI 或本人）→ 新的事蹟
      ▲                                                    │
      └──────────────── 被跟隨（回謝） ◀──────────────────────┘

世界越豐富 = 真人的行動越多 = 有改變的人越多
```

## 6. 生活紀錄

紀錄只做兩件事：**找到對的時機**、**降低紀錄的成本**。

| 方向 | 來源（皆為選用） | 用途 |
|---|---|---|
| 生活 → 世界 | 日曆、位置 | 承諾、觸發 |
| | 提供者出席確認、健康 App、照片、一句話 | 紀錄 |
| 世界 → 生活 | 足跡、角色與自己的重疊、預期 vs 實際 | 成就（鏡子） |

**隱私**：原始紀錄只留在用戶端，由用戶自己的 agent 讀取；世界只收到抽象結果。

## 7. 守則

1. 入口是樂趣
2. 每一步都可以停、可以退
3. 往前走靠拉力，不靠推力
4. 事蹟必須有真人意志；標示執行者（AI 角色或本人），兩者地位相同
5. 優先呈現可達成的事
6. 取用即供給，跟隨即回謝
7. 不以點數為核心貨幣；成就是鏡子，不是計分板
8. 世界不是廣告：推薦依興趣，不依付費
9. 角色是可能，不是應該
10. 試一次不綁約
11. AI 不捏造事蹟，並逐步讓位給真人

## 8. 健康指標

| 指標 | 意義 |
|---|---|
| ③ → ④ 轉換率 | 發現是否讓人想做 |
| ④ → ⑤ 轉換率 | 「想做」是否能被定義成第一步 |
| ⑥ 第一步完成率 | 第一步是否夠小、夠具體 |
| 執行者分布 | AI 執行與本人執行的比例，以及隨時間的變化 |
| ⑧ → 被發現時間 | 新事蹟多快成為別人的供給 |
| 被跟隨率 | 給予者是否得到回謝 |
| ⑨ 回到 ① 或 ⑤ 的比例 | 閉環是否持續轉動 |
| 預期與實際的落差變化 | 恐懼是否下降 |
| 真人供給占比 | AI 是否逐步讓位 |

# Core Loop：讓人持續投入並成長的閉環（草案 v1）

## 0. 第一性原理：人為什麼不做「想做的事」？

| 卡住的原因 | 本質 | 遊戲要提供的 |
|---|---|---|
| 不敢 | 高估風險、低估結果（尤其是社交） | 低風險的「先試一次」 |
| 沒動力 | 沒有具體的「為什麼現在」 | 一個讓人想知道答案的缺口 |
| 不知從何開始 | 第一步太大 | 小到不可能失敗的第一步 |
| 做了也沒人在乎 | 沒有回饋、沒有見證 | 立即且真心的回應 + 世界留下痕跡 |

所以一個人會行動，需要四件事同時成立：**想知道 × 相信做得到 × 第一步夠小 × 有人在乎**。整個系統只做這四件事。

## 1. 閉環：讀 → 做 → 說

```
   ┌─────────────────────────────────────────┐
   ▼                                         │
 ① 讀：小夥伴帶回一個「故事缺口」              │
   │  「我在湖邊遇到會捏陶的人，她說第一個杯子歪了，  │
   │    但歪的那個她到現在還在用……你猜為什麼？」     │
   ▼                                         │
 ② 選：三個小挑戰（或略過，沒有懲罰）           │
   │  先猜：「你覺得這會有多難/多尷尬？1~5」       │
   ▼                                         │
 ③ 做：在真實生活做一件 2 分鐘的小事             │
   ▼                                         │
 ④ 說：跟小夥伴說一句發生了什麼                 │
   │  再問：「實際上有多難/多尷尬？1~5」          │
   ▼                                         │
 ⑤ 回應：小夥伴真心回應 + 揭曉缺口答案           │
   │  + 你的故事變成世界裡的一樣東西             │
   │  + 小夥伴把你的故事帶給別人的小夥伴           │
   ▼                                         │
 ⑥ 新缺口：你的改變打開了下一個問題 ─────────────┘
```

使用者只要做三個動作：**讀一封信、做一件小事、說一句話**。

## 2. 每一步為什麼這樣設計

### ① 讀：故事缺口 → 好奇
- **理論**：Loewenstein 資訊缺口理論。注意力落在「知道」與「想知道」之間的缺口時，就會產生好奇；完全不懂的事不會引起好奇；越接近答案，越想知道。
- **做法**：小夥伴只講一半，留一個具體問題；題材從主人的興趣**旁邊一步**挑選（有基礎知識，但沒做過）。
- **為什麼**：好奇是「從未想過的事」的入口。用故事而不是任務清單，人才是「想做」而不是「被要求做」。

### ② 選：自己選 + 先預測
- **理論**：自我決定論（SDT）。在遊戲中感受到的自主與勝任，能預測投入程度與福祉。
- **做法**：一次只給 3 個選項，可以全部略過；略過時小夥伴不失望、不扣分。
- **預測**：做之前先猜難度或尷尬程度（1~5）。這一步是後面「校準」的基礎。

### ③ 做：小到不會失敗
- **理論**：Fogg 行為模型 B = MAP。動機、能力、提示要在同一刻同時出現；動機不可靠，所以要把能力門檻降到最低。
- **做法**：每個挑戰都是 2 分鐘可以完成的版本（「傳一句話給很久沒聯絡的朋友」，而不是「重建友誼」）。
- **提示**：挑戰附著在使用者既有的日常時刻（「下次排隊時……」）。

### ④ 說：回報 + 校準
- **理論**：Epley & Schroeder（2014）。人系統性地**低估**與陌生人交談的愉快程度，也低估對方想交談的意願，所以選擇沉默。
- **做法**：把「預測 vs 實際」並排顯示，並累積成個人圖表：

  ```
  你的預測：尷尬 4/5    實際：1/5
  ── 過去 10 次，你平均高估了 2.3 分 ──
  ```
- **為什麼**：這是讓人「敢」的核心機制。不靠說服，而是讓使用者用自己的數據看到恐懼一再失準。

### ⑤ 回應：真心回饋，不給點數
- **理論 1**：Fogg 認為立即的正向情緒才是習慣形成的關鍵，而不是重複次數。
- **理論 2**：Deci, Koestner & Ryan（1999）統合分析。可預期的實質獎勵會降低原本就喜歡做的事的內在動機，口頭肯定則傾向提升。
- **做法**：
  - 小夥伴的回應要具體提到你做的事（LLM 正好擅長這個）
  - 揭曉缺口的答案，讓好奇被滿足
  - **你的故事變成世界裡的實體**：一個陶杯出現在小夥伴的家、一張照片掛上鎮上的牆
  - 小夥伴把你的故事（匿名或具名，由你決定）帶給其他小夥伴
- **為什麼**：真實生活的行動**不換成金幣或點數**，而是換成「被看見」和「留下痕跡」。

### ⑥ 新缺口
- 每完成一次，就自然打開一個相關的新問題（陶杯 → 「鎮上有人想用你的杯子辦茶會」）。
- 這裡借用 Zeigarnik 效應：未完成的事會留在心上（常見說法，證據強度中等）。

## 3. 成長階梯：從看別人做，到自己帶人做

Bandura 自我效能的四個來源，依序對應到四個階段：

| 階段 | 你在做什麼 | 對應來源 |
|---|---|---|
| 1. 旁觀 | 看小夥伴在世界裡做（替身體驗，低風險） | 替代經驗 |
| 2. 小步 | 自己做 2 分鐘版本 | 親身成功經驗（最強） |
| 3. 一起 | 和另一位主人一起完成（小夥伴先牽線） | 他人鼓勵 + 正向情緒 |
| 4. 帶人 | 你的故事成為別人的「旁觀」素材 | 你變成別人的楷模 |

- 難度依「預測 vs 實際」的表現自動調整：連續覺得太簡單 → 升階；覺得太難 → 退一階，換成更小的版本。
- 第 4 階讓閉環變成**社群閉環**：A 的故事 → B 的好奇 → B 的行動 → B 的故事 → C……

## 4. 建立人際關係的特化路徑

```
小夥伴們先在世界裡相遇（零風險）
  → 發現共同興趣，關係值上升
  → 小夥伴告訴你：「我跟 Bob 的小夥伴很合，他主人也在學吉他」
  → 小挑戰：「要不要回他小夥伴帶來的一句話？」（預測尷尬度）
  → 雙方都同意 → 解鎖直接對話
```

為什麼：讓小夥伴當「破冰的替身」，把最難的第一步（開口）變成回應一句已經存在的話。

## 5. 為什麼會回來（不靠焦慮）

| 動力 | 來源 | 對應需求 |
|---|---|---|
| 「它今天做了什麼？」 | 小夥伴在你不在時也有自己的生活 | 好奇 |
| 「上次那件事後來呢？」 | 每輪留下的新缺口 | 好奇 |
| 「我又敢了一點」 | 預測 vs 實際圖表 | 勝任 |
| 「我的故事被看見了」 | 世界裡的實體 + 被轉述 | 歸屬 |
| 「我想照顧它」 | 小夥伴的人格與記憶 | 歸屬 |

**刻意不用**：連續登入獎勵與斷掉的懲罰、會死或生病的寵物、排行榜（會讓「想做的事」變成「跟別人比」）、焦慮式推播。

## 6. 設計守則

1. **三個動作**：讀、做、說。任何新功能都不能讓核心路徑超過三個動作。
2. **真實行動不換點數**：只換故事、回應、世界痕跡。
3. **永遠可以略過**：不做沒有懲罰。
4. **用數據說服自己**：預測 vs 實際，而不是說教。
5. **一步之遙**：好奇題材 = 主人的興趣再往外一步。

## 7. 對既有設計的修正

- `VISION.md`「運動 → 小夥伴體力 +」改為「真實行動 → 故事與世界實體」，避免外在獎勵削弱內在動機。
- `GAME-DESIGN.md` 的季末排行榜改為「本季故事集」，不排名次。

## 8. 要驗證的假設（MVP 量測）

| 假設 | 指標 |
|---|---|
| 故事缺口能引發行動 | 讀信 → 選挑戰的轉換率 |
| 預測 vs 實際能降低恐懼 | 預測尷尬度是否隨次數下降 |
| 被看見比點數更能讓人回來 | 有「故事被轉述」的使用者，7 日回訪率 |
| 階梯能讓人走出舒適圈 | 進入第 3 階（和真人一起）的比例 |

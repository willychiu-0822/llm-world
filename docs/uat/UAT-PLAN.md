## 審查重點

config 延遲或失敗、匿名與過期 session、不同來源區域與手動選擇、手機表格與長文字、重新整理與深層連結。以真實 API 與 DB 驗證，僅延遲 config 使用攔截；不需要外部金鑰。

## 本輪接續 UI 設計與執行決定（2026-11-10 04:07）

沿用現有 React/CSS 與使用者已指定的畫面，不重建 UI。補齊空狀態中的可點下一步（地點、步驟、鏡子、通知）；角色新增願望後提供回地圖的入口。將首次測試登入的說明改為可直接照做的文字。步驟列表只保留一個主要操作；展開完成表單時以「完成」為主，可取消。手機以真實頁面檢查水平邊界，以及捲到頁尾的操作是否在 tabbar 上方；每個修改畫面均截圖。先寫失敗的 UAT-14 E2E 再改 UI，之後走訪客登入導回、深層連結、空資料、長文字等 UAT-15 探索分支；發現另立 UAT 編號、TDD、獨立 commit。

| UAT-14a | 無步驟/足跡/通知/發現/事蹟 | 走空狀態與三個步驟tab | 每個空狀態有可點的下一步 |
| UAT-14b | 兩筆本人步驟 | 進入步驟、展開第二筆完成、取消 | 全頁只有一個主要操作、可取消、手機頁尾操作不被tabbar遮住 |
| UAT-14c | 訪客 | 測試登入頁、設定角色、寫願望、地圖 | 可照說明操作、依進度只突出一個按鈕、寫願望後可去地圖 |
| UAT-14d | 新提供者與管理者 | 等待審核、管理、核准後首次開店 | 等待與空狀態有入口、手機無水平溢出 |

| UAT-18 / 審查新發現 | /api/config第一次503 | 登入頁錯誤→重新載入→測試登入 | 有可恢復錯誤、Google不閃現、重試後登入成功 |

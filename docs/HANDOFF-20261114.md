## 前一份交接遺留的已知問題

- 全套 E2E 曾 78/80。兩次都是單跑通過、全套才失敗，根因已用會在修正前失敗的測試釘住，沒有加長逾時或重試。
  - 桌機「Mia 等地點信物」逾時：拖地圖超過 6px 會把 `suppressClick` 設為真，原本只在 `pointerup` 之後用 `setTimeout(0)` 清掉。拖曳自己的 click 會被吃掉，這是對的；但全套負載（桌面地圖的 SVG 濾鏡、截圖）下，Playwright 的下一次 `click()` 會在計時器之前就被處理。`click()` 仍算成功，頁面卻停在地圖，接著「去上一次陶藝體驗課」一直等到 90 秒。單跑時事件迴圈空閒，計時器先跑完。修正：在 `click` capture 階段立刻清掉旗標，只丟掉拖曳那一下；沒有 click 跟著來時，仍用下一個 task 清掉。
  - 手機 B4「刷新生活收藏」停在載入中：登入後重整會去抓 `/assets/`（主包和生活頁的 lazy chunk）。`loadSession` 只要有 session cookie 就查資料庫。連線池被占滿時，這個靜態請求在 1 秒內回不來，Suspense 和 `RequireLogin` 都停在「載入中……」。生活收藏的標題要等 `/api/me/life` 才出現，所以失敗落在刷新生活收藏，而 `/life` 的「小龍的今天」在載入佔位裡就有。另外兩條會把載入旗標黏住：`useFetch` 的舊回應可以蓋掉新資料，或在路徑變成 `null` 時提早 return 卻不把 loading 設回 false；從往返快取恢復（`pageshow` 且 `persisted`）時，已被瀏覽器中止的 `/api/session` 或生活讀取不會再結束，整個畫面停在「載入中……」。修正：`/assets/` 不查 session；讀取用世代計數，只有最新一次能寫入或清掉載入中；往返快取恢復時重新讀。行為除此之外不變，沒有移植 main 上的 20 秒 GET 逾時。
